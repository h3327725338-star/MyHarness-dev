# Tool description
- Hand in your final report with submit_report as the last step, alone in its reply; a successful call ends the task. Put the complete report in report, or leave report empty when the same reply already holds it as text.
- When the task lists Questions, give one entry per question in the same order with a status: answered, partial, unavailable (you investigated, but the material does not exist or cannot be reached: say where you looked and what blocked you), or not_done. Every status other than answered needs a note.
- A rejected call says what to fix; fix it and call again. Never end the task without a successful submit_report call.
